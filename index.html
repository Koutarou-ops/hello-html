大学生のための Claude Code 8週間学習プラン

はじめに

この学習プランのゴール

8週間後に、次の3つができている状態を目指します。

1

Claude Code を使いこなせる

指示の出し方、変更の確認、GitHub との連携を自分でできる

2

自分の成果物が公開されている

毎週の成果物が GitHub に、Web アプリが URL で公開されている

3

インターンに応募できる

GitHub・README・ポートフォリオを揃え、面接で「何を作り、AI とどう協力し、自分が何を判断したか」を話せる

時間の目安

1週あたり

約10時間

平日1時間 × 5日 ＋ 週末5時間 など

前半4週

Claude Code に慣れる

後半4週

ポートフォリオアプリを作る

進め方の4つの原則

1

読んで説明できるコードだけを残す。

Claude が書いたコードでも、あなたが説明できなければ面接で困ります。分からない箇所は「この部分を初心者向けに説明して」と聞きましょう。

2

小さく頼んで、すぐ確かめる。

「アプリ全部作って」ではなく「ログイン画面だけ作って」→ 動作確認 → 保存（コミット）を繰り返します。

3

承認ボタンを読まずに押さない。

Claude がファイルを変更したりコマンドを実行する前に確認が出ます。何をしようとしているか必ず読みましょう。

4

作ったものは毎週 GitHub に公開する。

採用担当者はコードだけでなく、コミット履歴から成長の過程も見ます。API キーなどの秘密情報は公開しないこと。

全体スケジュール

毎週の終わりに、その週の成果物を GitHub に push して公開します。第1〜2週の分は、第3週で GitHub の使い方を覚えたときにまとめて公開します。

週 テーマ その週の成果物
1準備と最初の対話簡単な HTML ページ
2基本操作と指示の出し方小さな Web ツール（割り勘計算など）
3GitHub 連携と CLAUDE.mdGitHub の公開リポジトリ
4Web アプリの基礎と公開URL で見られる自己紹介サイト
5ポートフォリオアプリの企画・設計仕様書 docs/spec.md と画面ラフ
6実装①：主要機能主要機能が動く版
7実装②：品質を上げる公開済みの完成版
8仕上げと応募準備応募パッケージ一式

第1週：準備と最初の対話

学習目標

  • デスクトップアプリの Code タブでプロジェクトを開き、Claude と会話できる
  • 「権限確認」の意味を理解する

最初にフォルダ構成を作る

8週間の成果物を 1 か所にまとめるため、最初のセッションで次の構成を Claude に作ってもらいます。

claude-learning/
├── CLAUDE.md        ← 全プロジェクト共通のルール
├── plan/            ← 学習計画書（この資料の PDF）
├── notes/           ← メモ
│   ├── week01.md    ← 週ごとの振り返り
│   └── prompts.md   ← うまくいった指示集
└── projects/
    ├── 01-hello-html/      ← 第1週
    ├── 02-warikan/         ← 第2〜3週
    ├── 04-profile-site/    ← 第4週
    └── 05-portfolio-app/   ← 第5〜8週
  • フォルダ名は英数字とハイフンだけにする。日本語やスペースは、ツールや URL でトラブルの元になります
  • projects/ の中は週番号を付け、作った順に並ぶようにする
  • 1 プロジェクト = 1 つの GitHub リポジトリにする。claude-learning 自体は Git 管理しない（メモが公開されるのを防ぐため）
  • 2 回目以降は、作業するプロジェクトのフォルダを開いてセッションを始める。上の階層の CLAUDE.md も自動で読まれるので、共通ルールは claude-learning/CLAUDE.md に書く
  • 振り返りは notes/week01.md のように週ごとに書き、うまくいった指示は notes/prompts.md に貯める。第8週の README と面接準備の材料になります
ホームフォルダに claude-learning というフォルダを作り、次の構成にしてください。
plan/、notes/、projects/ の3つのフォルダと、直下に CLAUDE.md を置きます。
CLAUDE.md には「説明は日本語で初心者向けにする」と書いてください。
作ったら、どんな構成になったか見せてください。

やること

やること完了
Claude デスクトップアプリをインストールしてログインする
上の構成で claude-learning フォルダを作り、plan/ にこの学習計画書の PDF を入れる
画面の各部分を確認する（チャット欄、差分ペイン、ブラウザペイン、権限モードの切替）
権限確認のダイアログが出たら、何をしようとしているかを読んでから 許可する
Git と Node.js が入っているか Claude に確認してもらい、無ければインストール手順を案内してもらう
projects/01-hello-html に簡単な HTML ページを作ってもらい、ブラウザペインで表示する
そのページのコードを 1 行ずつ説明してもらう

Claude への指示例

このフォルダに、自己紹介を1段落だけ書いた index.html を作ってください。
CSS は同じファイルの中に書き、背景を薄い青にしてください。
作ったらブラウザで表示して確認してください。
いま作った index.html を、プログラミング初心者にも分かるように
上から順に説明してください。HTML タグの役割も教えてください。

振り返り

  • Claude が「許可」を求めてきたのはどんな操作でしたか？
  • 自分で説明できない行はありましたか？

第2週：基本操作と指示の出し方

学習目標

  • 良い指示（目的・制約・完了条件）を書ける
  • 差分を読んで、変更を受け入れるか判断できる
  • 失敗したときにやり直せる

やること

やること完了
Plan モード を使い、実装前に計画だけを出してもらう
@ファイル名 でファイルを指定して質問する
差分ペインで「何行消えて何行増えたか」を確認する
わざと気に入らない変更を頼み、元に戻す方法を試す
話題が変わったら 新しいセッション を始める（会話が長くなると精度が落ちるため）
projects/02-warikan に割り勘計算ツールを作る（人数と金額を入れると 1 人あたりの金額が出る）

良い指示の型

【目的】飲み会の割り勘を計算する Web ページを作りたい
【制約】HTML・CSS・JavaScript の 1 ファイルで。ライブラリは使わない
【完了条件】金額と人数を入れてボタンを押すと、1 人あたりの金額が
            100 円単位で切り上げて表示される。人数が 0 のときはエラー表示

振り返り

  • 「目的・制約・完了条件」を書いた場合と書かなかった場合で、結果はどう違いましたか？
  • Plan モードで出た計画に、自分で修正を入れた点はありますか？

第3週：GitHub 連携と CLAUDE.md

学習目標

  • Git の基本（コミット・ブランチ・プルリクエスト）の意味が分かる
  • CLAUDE.md で Claude に「このプロジェクトのルール」を伝えられる

やること

やること完了
GitHub アカウントを作成し、Claude に GitHub との連携設定を手伝ってもらう
01-hello-html と 02-warikan をそれぞれ GitHub の公開リポジトリにする（1 プロジェクト = 1 リポジトリ）
「コミット」「ブランチ」「プルリクエスト（PR）」を Claude に説明してもらう
新しいブランチで機能追加（例: 端数の扱いを選べる）→ PR を作成 → 内容を確認してマージ
/init でプロジェクト用の CLAUDE.md を作る。全体共通のルールは claude-learning/CLAUDE.md に書き分ける
README.md（使い方・スクリーンショット）を書いてもらう

CLAUDE.md に書く例

# ルール
- 説明は日本語で、初心者向けに書く
- 変更したら、何を変えたかを 3 行でまとめる
- コミットメッセージは日本語で「何をしたか」を書く

振り返り

  • コミットを細かく分けると、後で何が嬉しいでしょうか？
  • CLAUDE.md を書く前と後で、Claude の返答は変わりましたか？

学習目標

  • 「誰の・どんな困りごとを・どう解決するか」を言葉にできる
  • 作る前に仕様書を書く習慣をつける

やること

やること完了
題材を決める（付録「アプリ題材アイデア」参照）。自分や身近な人が実際に困っていること が一番強い
Claude と壁打ちして、機能を「必須」「あれば嬉しい」に分ける

仕様書に書く項目

## 解決したい課題（誰が・何に困っているか）

第6週：実装①（主要機能）

学習目標

  • 「小さく実装 → 確認 → コミット」のサイクルを回せる
  • データベースにデータを保存・表示できる

やること

やること完了
Issue を 1 つずつ選び、ブランチを切って実装する
1 機能ごとにブラウザペインで動作確認し、コミット・PR にする

Claude への指示例

docs/spec.md の「予定の登録」機能だけを実装してください。
他の機能には触れないでください。
実装後はブラウザで、予定を 1 件登録して一覧に表示されるところまで確認してください。

振り返り

  • AI を使った開発について、自分の判断を語れる

やること完了

README テンプレート

# アプリ名
公開URL: https://...

## 作った理由（どんな課題を解決するか）
## 主な機能（スクリーンショット付き）
## 使用技術
## 工夫したこと・苦労したこと
## Claude Code の使い方（自分が判断したこと / AI に任せたこと）
## 今後やりたいこと

面接で聞かれそうなこと

  • なぜこのアプリを作ったのですか？
  • AI が書いたコードを、どうやって正しいと確かめましたか？
  • AI の提案を採用しなかった場面はありますか？
  • 一番難しかったバグと、その解決方法は？
  • もう一度作るとしたら、何を変えますか？

ポイント: 「AI に作らせました」ではなく、「課題を定義し、仕様を決め、AI の出力を検証して取捨選択した」 と語れることが評価につながります。
